## Implemented fix

An already confirmed idle release needs neither a ping nor a stop request. Otherwise, a successful ping records the native session identity, and handover waits up to five seconds for that session's final acknowledgement. A health timeout alone, consumed stop file, wrong session/version, dispatcher error, modal or busy handler cannot authorize the legacy tool. Unconsumed stop files are removed on exit.

Older scripts without session acknowledgements, or a workspace without a confirmed session, now refuse handover. Establish a session through the updated coordinated EDA entry point (`app_context`) before using the legacy bridge. A hung script needs inspection; retrying a tool is not evidence that it stopped.

## Validation

Before the first fix, seven of eight shutdown regressions failed. The final root suite passes 135 tests, covering shutdown confirmation, cancellation under both asyncio and AnyIO, malformed launch records and wrapper dispatch guards. Invalid-state tests use temporary files rather than corrupting the production workspace.

The changed coordinator and legacy wrapper were deployed with backups; initialization of both installed servers passed (447 EDA tools, 37 legacy tools). Existing server processes need reconnecting to load the updated Python modules.

### Follow-up fixes and live verification

The two remaining findings above are now fixed. `run_engine_worker` shields non-cancellable thread work from AnyIO scopes and repeated `Task.cancel()` calls, keeps the shared lock until completion, and delivers pending cancellation before dispatching a legacy tool. Malformed/unreadable launch records no longer silently bypass the cooldown or raise incidental type errors. A successful health probe can retire stale launch state; otherwise, an operator-confirmed manual stop permits clearing it through the existing reset command.

The installed copy passed a live stdio test against open Altium: EDA stop/restart, legacy `get_all_designators`, return to EDA, idle release despite pings, and restart after idle. Separate live cancellation tests passed during real `stop_eda` and `start_eda`: the lock remained held until native completion, cancellation reached the caller, and shutdown was confirmed at exit. SHA-256 verification confirmed that all 13 project/schematic/PCB files retained their original contents.

No change to the native idle-release interval, design files, or variant serialization was required.
