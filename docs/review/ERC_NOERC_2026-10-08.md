# ERC / scoped NoERC integration, 2026-10-08

Source changes in Generic.pas, Project.pas and Main.pas preserve the storage3 working changes. Running/deployed version: 2026.10.08.noerc5.

- Generic properties now type-check ISch_NoERC before exposing IsActive, SuppressAll, StrErrorKindSetToSuppress and StrConnectionPairsToSuppress. `NetWithNoDrivingSource` uses the native enum/set serializer. For an exclusive category waiver, set SuppressAll=false AND clear connection-pair suppressions; factory defaults contain all connection pairs.
- Native IViolation.DM_ErrorLevel / DM_IsSuppressed / DM_ErrorKind are returned. Project Messages excludes suppressed violations when DM_ReportSuppressedErrorsInMessages is false. The raw ERC list retains suppressed entries explicitly.
- ERC dispatch uses native DM_CompileEx(True, Cancelled) and DM_Validate instead of the unconfirmed Sch:ERC process. Cancellation/non-completion returns an error. Force-recompile also resets native document compile timestamps.

Live verification on RV1106G3_Header_Board.PrjPcb: five category-specific markers, empty connection-pair lists, unchanged 647 pin/net rows, unchanged component parameter values and pin properties, unchanged ERC matrix/variants. After save/reopen/load all 11 sheets: zero active messages. Disabling the USB marker and reopening restored exactly USB_VBUS_IN; disabling 17 existing unused-memory-pin markers added no warnings. All were restored and the final reopened project had zero active messages.

## Known limitation

Neither DM_CompileEx(All=True), DM_ResetLastCompileTimeForAllDocuments nor DM_Validate alone refreshed the workspace validation model after some scripted primitive/property edits in this session. The on-disk edits and SchServer readbacks were correct, but validation still described the old fractional label position and old NoERC active states. Closing/reopening the saved PCB project and reloading its sheets refreshed the model. Do not interpret a fresh Python compile tick as proof of a fresh Altium validation model. The next fix needs the documented editor-to-workspace model-change notification plus a native readback test; do not paper over it by changing pin electrical types or global ERC modes.

UI panel discovery also failed for a Messages panel the user reported open; menu discovery reported an empty popup. Task-local COM/DPI/foreground experiments did not establish a reliable fix and were not deployed to production sources. No claim that UI discovery or all cache issues are fixed.

Validation: native Altium API readbacks above; 22 existing query/variant/deployment regression tests passed. No new redundant source-shape tests. Nothing committed or pushed by this Messages review.
